# Repository Guidelines

## Project Overview

`f1-telem` is a zero-dependency, zero-allocation Rust library that parses UDP telemetry datagrams from EA Sports F1 23, F1 24, F1 25, and the F1 25 2026 Season Pack (packet format 2026, `v2026`). Packet struct definitions are generated at compile time from YAML specifications via `build.rs`—there is no hand-written decoding logic for individual packet types.

## Architecture & Data Flow

```
spec/*.yaml ──► build.rs (serde_yaml, resolves `extends`) ──► $OUT_DIR/generated.rs
                                                                    │
src/generated.rs  ◄── include!() ──────────────────────────────────┘
       │            (v20XX modules, `common` view, GameVersion, PacketKind, Packet)
src/lib.rs  ──► parse_packet(&[u8]) -> Result<Packet, ParseError>
       │
       ├─ header.rs    – 29-byte PacketHeader (hand-written), parse_header()
       ├─ reader.rs    – Reader cursor + `Decode` trait: little-endian, no-alloc
       ├─ fixed_str.rs – FixedStr<N>: inline NUL-padded string, UTF-8 checked lazily
       └─ error.rs     – ParseError enum (manual Display/Error impls)
```

**Runtime parse path:**

1. `parse_packet(data)` checks ≥29 bytes, then calls the generated `Packet::decode`.
2. `Packet::decode` peeks `packet_format` and dispatches to `v20XX::Packet::decode`.
3. Version `decode` reads the header, matches `packet_id`, checks the declared size, and calls `PacketX::decode_body(header, reader)`, which reads fields sequentially in little-endian order.
4. Returns `Packet::F1_23(v2023::Packet)` | … | `Packet::F1_26(v2026::Packet)`.
5. `Packet::visit(&mut impl common::PacketVisitor)` calls the visitor method for the packet kind with the version-specific packet, which implements the matching `common::Packet*` trait.

**Cross-version view (`common`, generated by `emit_common` in `build.rs`):** one trait per struct and per packet name across all specs, implemented by every version's type. Field types are unified: integers widened to the smallest type holding all versions, `scale`d or mixed int/float fields become `f32`/`f64` physical values, differing array lengths become slices, strings `Cow<str>`, fields missing in some version `Option`. Fields whose types cannot be unified are omitted from the trait; each omission prints a `cargo::warning` at build time and is listed in the trait's (or event variant's) doc comment. Struct-typed fields use associated types; versions lacking the struct use `common::Absent` (uninhabited). `common::EventDetails` is the union of all events (scalar fields only) with `From<&vXXXX::EventDetails>`. `common::PacketVisitor` has a default no-op method per packet kind.

## Key Directories

| Path | Purpose |
|---|---|
| `src/` | Library crate root and core modules |
| `src/bin/listen.rs` | Example binary—binds UDP socket, parses & prints packets to stdout |
| `spec/` | YAML packet specifications per game year (source of truth for codegen) |
| `build.rs` | Build script: YAML → Rust codegen with compile-time size validation |
| `tests/` | Integration tests for packet parsing |
| `docs/` | Official EA/Codemasters specification documents (PDF, DOCX, TXT) |

## Development Commands

```sh
cargo build          # Triggers build.rs codegen from spec/*.yaml
cargo test           # Runs unit tests (header, reader) + integration tests (packet_parse)
cargo run -- [ADDR]  # Runs listen binary; defaults to 0.0.0.0:20777 (UDP)
```

No linter, formatter config, or CI pipeline is checked in. Use `cargo fmt` and `cargo clippy` conventionally.

## Code Conventions & Common Patterns

### Naming
- Structs: `PascalCase` matching the telemetry spec (e.g., `PacketCarTelemetryData`).
- Fields: `snake_case`, translated from the C++ `m_` prefix originals (e.g., `m_aiControlled` → `ai_controlled`).
- Modules: version modules named `v2023`, `v2024`, `v2025`, `v2026`.

### Error Handling
- Custom `ParseError` enum (`#[non_exhaustive]`) in `src/error.rs` with manual `std::fmt::Display` and `std::error::Error` impls (no `thiserror`/`anyhow`).
- Variants: `BufferTooShort`, `UnsupportedFormat(u16)`, `UnknownPacketId { packet_id, format }`, `SizeMismatch`.
- Unknown event codes are not errors: they decode to `EventDetails::Unknown { code, payload }`. Invalid UTF-8 in names is not an error: `FixedStr::as_str()` reports it on access.

### No External Runtime Dependencies
- Zero crate dependencies at runtime. `serde` and `serde_yaml` are build-dependencies only.
- No async runtime—the listen binary uses blocking `std::net::UdpSocket`.
- No unsafe code or FFI.

### Reader Pattern
`Reader` (`src/reader.rs`) wraps `&[u8]` with a position cursor. Methods: `read_u8`, `read_i8`, `read_{u16,i16,u32,i32,u64,f32,f64}_le`, `read_u8_array::<N>`, `read_array::<T, N>` (`T: Decode + Default + Copy`), `read_fixed_str::<N>`, `peek_u16_le`, `skip`. All little-endian, all return `Result<T, ParseError>`. No allocations on the parse path.

All primitives, `FixedStr<N>`, `PacketHeader` and every generated struct implement `reader::Decode`.

### Code Generation
- `build.rs` loads every `spec/*.yaml`, resolves `extends` chains, sorts versions by `packet_format`, validates (packet sizes = header 29 + body, event payloads fit, no duplicate names/ids/codes, unknown YAML keys rejected), then emits one module per version plus the crate-level `GameVersion`, `PacketKind` and `Packet`.
- Generated code lives in `$OUT_DIR/generated.rs`, pulled in via `include!` in `src/generated.rs`.
- `cargo::rerun-if-changed` is set for `build.rs`, the `spec/` directory, and each spec file.
- All generated and public enums are `#[non_exhaustive]`.

### YAML Spec Schema
Each `spec/f1_YYYY.yaml` declares:
- `version`: `{ format, year, module }` (e.g. `2025`, `25`, `v2025`); `GameVersion::F1_{year}` is derived from it
- `extends` (optional): file stem of the parent spec (e.g. `f1_2024`); the child lists only differences
- `remove` (optional): `{ structs: [names], packets: [ids], events: [codes] }` dropped from the parent
- `consts` (optional): named array lengths, e.g. `cars: 22`; inherited, and a child override also resizes inherited arrays
- `sizes` (optional): `{ <packet id>: <bytes> }` declared-size overrides for inherited packets the child does not restate (e.g. after changing `cars`)
- `structs`: reusable sub-structures; replace a parent struct with the same `name` in place, else append
- `packets`: `{ name, id, size, fields }`; replace by `id`. The event packet is `{ name: Event, id: 3, size: 45, event_packet: true }` with no fields
- `events`: `{ name, code, fields }`; replace by `code`. Payload size = event packet size − 29 − 4
- Field types: `u8 i8 u16 i16 u32 i32 u64 f32 f64`, `string(N)` (→ `FixedStr<N>`), `[T; N]`, struct names. `N` may be a number, a constant, or a product such as `50 * cars`. Nested arrays (`[[T; N]; M]`) are rejected; wrap the inner array in a struct. Event codes must be 4 printable ASCII chars (no quote or backslash).
- Field option `scale`: marks a quantised value, physical = raw × scale (e.g. 2026 g-force `{ name: g_force_lateral, ty: i16, scale: 0.001 }`). Only on integer fields up to 32 bits (`u8`–`i32`), and the value must be positive and finite. The raw integer is kept; the generated field documents the factor, and the `common` accessor returns the physical value (dividing by N when the scale is exactly 1/N, as EA's docs phrase it).

### Adding a Game Version
Add `spec/f1_YYYY.yaml` with `extends:` the previous year and only the changed structs/packets/events. A packet whose fields change is restated; a packet that only changes size (e.g. through a struct or `consts` change) gets an entry in `sizes`. No Rust changes are needed: the version module, `common` trait impls and visitor dispatch are generated, and `src/bin/listen.rs` prints every version through the `common` view (add a visitor method there only to print a newly introduced packet kind).

## Important Files

| File | Role |
|---|---|
| `src/lib.rs` | Crate root: module declarations, re-exports, `parse_packet()` entry point |
| `src/generated.rs` | `include!` bridge to build-generated version modules and version enums |
| `src/reader.rs` | Zero-alloc binary cursor and `Decode` trait used by all decoders |
| `src/fixed_str.rs` | `FixedStr<N>` inline string type for name fields |
| `src/header.rs` | `PacketHeader` struct, `parse_header()`, `HEADER_SIZE` constant (29) |
| `src/error.rs` | `ParseError` enum |
| `src/bin/listen.rs` | CLI binary: UDP recv → `parse_packet` → one `common::PacketVisitor` printer for all versions |
| `build.rs` | Codegen: YAML specs → version modules, `common` view, `GameVersion`, `PacketKind`, `Packet` |
| `spec/f1_2023.yaml` | Base spec (complete); `f1_2024.yaml`, `f1_2025.yaml` and `f1_2026.yaml` (2026 Season Pack) extend it as diffs |

## Runtime/Tooling Preferences

- **Language:** Rust, edition 2021.
- **No MSRV** specified.
- **No runtime dependencies.** Build deps only: `serde`, `serde_yaml` (for `build.rs`).
- **No feature flags** defined.
- **No workspace**—single crate.
- **Package manager:** Cargo (standard).

## Testing & QA

### Test Structure
- **Unit tests:** Inline `#[cfg(test)] mod tests` in `src/header.rs`, `src/reader.rs`, and `src/fixed_str.rs`.
- **Integration tests:** `tests/packet_parse.rs`—imports `f1_telem::*` and exercises the public `parse_packet` API.

### Test Data
All packet bytes are synthetically constructed in-memory using a `PacketBuilder` helper defined in the test file. Methods: `.header()`, `.u8()`, `.u16()`, `.u32()`, `.u64()`, `.i8()`, `.f32()`, `.string()`, `.zeros()`, `.pad_to()`. No external fixture files.

### Naming Convention
- Standard packets: `f1_YY_<packet_type>` (e.g., `f1_23_motion_packet`)
- Changed fields: `f1_YY_<packet>_with_<feature>` (e.g., `f1_25_car_damage_with_blisters`)
- Events: `f1_YY_event_<event_type>` (e.g., `f1_24_event_safety_car`)
- Errors: descriptive snake_case (e.g., `buffer_too_short_for_body`)

### Assertion Patterns
- `assert_eq!` for integers, strings, lengths.
- `assert!((val - expected).abs() < 0.001)` for floats.
- `assert!(matches!(…))` for enum variant checks.
- `if let … else { panic!("…") }` for deep destructuring.

### Coverage
All 14 base packet types are tested for F1 23. F1 24, F1 25 and 2026 tests target additions and structural changes (new packets, new fields, widened/narrowed types, updated events). Error and forward-compatibility paths (unsupported format, unknown packet ID, unknown event code → `EventDetails::Unknown`, invalid UTF-8 names, truncated and oversized buffers) are explicitly tested, as are the generated `GameVersion`/`PacketKind` tables.
